### Что в API есть и чего нет (важно для логики)
- Есть: цена USD, `export_fee_usd`, `port_fee_usd`, год, пробег, топливо, КПП, кузов, привод, комплектация (`spec.name`), до ~30 фото, полные `spec_groups` (в т.ч. `Maximum horsepower (Ps)`, кВт мотора).
- **Нет фильтра по мощности.** Мощность лежит строкой в `engine` (`"Range Extender 156 HP"`) и в `spec_groups`. Для правила «проходной до 160 л.с.» нужно поле `power_hp` + фильтр `power_max` → **задача Игорю**.
- Фото — хотлинк на `autoimg.cn` (CDN che168). Для сайта их **нельзя отдавать напрямую**: ссылка может умереть и палит источник/цену донора.
- В карточке есть `detail_url`, `whatsapp_url` дилера — **никогда не выводить клиенту**.

## 1. Ключевое решение по спору «парсер vs ручные карточки»

Руслан: «проще вручную, карточки висят годами, парсер грузит мусор». Никита: «с парсером быстрее — характеристики подтягиваются сами».

**Решение: оба способа = одна сущность «Карточка витрины».** Не объявление, а *модель-предложение* («Mazda CX-5 2.5 AWD 2023 — от 2,9 млн ₽»).

- **Создать с нуля** — пустая форма, Руслан сам пишет всё и грузит свои фото.
- **Создать из объявления** — в админке парсера кнопка «В витрину» → форма предзаполнена (марка, модель, комплектация, год, л.с., объём, привод, КПП, фото), Руслан правит и публикует.
- После создания карточка **не зависит от парсера**: объявление на che168 продалось — карточка продолжает висеть. Связь `source_infoid` хранится только для справки.

Так парсер становится «автозаполнением формы», а не источником мусора на сайте. Спорить больше не о чем.

### Почему витрина живёт в бэкенде Игоря, а не в Next.js
БД, логин в админку и парсер там уже есть — добавить 2–3 таблицы и экран дешевле, чем поднимать вторую админку/CMS.

### Как сайт получает данные
Сейчас сайт статический (`output: export`). Варианты:

| Вариант | + | − |
|---|---|---|
| **A. Пересборка по кнопке** — в админке «Опубликовать» дёргает webhook → `deploy.sh` (build + rsync) | Остаётся статика, SEO идеальное, сервер не нужен | Публикация 1–3 мин; нужен build-сервер/CI |
| **B. Next.js в режиме сервера + ISR** (`next start` под pm2, `revalidate`) | Изменения видны сразу, on-demand revalidate из админки | Нужен Node-процесс на сервере, правка `next.config.ts` |
| C. Клиентский fetch из браузера | Проще всего | Плохо для SEO — карточки не индексируются |

**Рекомендация: A на старте** (карточек мало, меняются редко — Руслан сам сказал «один раз загрузил и висит»), перейти на B если начнут публиковать ежедневно.

## 3. Модель данных

| Поле | Тип | Комментарий |
|---|---|---|

| year_from, year_to | int | диапазон, т.к. это предложение, а не конкретная машина |
| condition | new / used | |
| body, engine_type, drive, gearbox | enum | маппинг EN→RU (см. §5) |
| displacement_l, power_hp, consumption | | |
| **utilization_ok** | bool | «проходной» — автоматически по power_hp ≤ 160 и возрасту, можно переопределить вручную |
| price_from_rub | int | **отображаемая цена «от»**; авторасчёт + ручной оверрайд |
| price_calc_json | json | из чего посчитано (для админа) |
| eta_days_from/to | int | срок доставки |
| photos[] | файлы | **скачанные к себе** (S3/диск), сортировка, обложка; можно залить свои в едином стиле |
| summary, highlights[] | text | короткое описание как в постах TG-канала |
| is_published, is_hit, sort_order | | «хиты» на главную, порядок перетаскиванием |
| updated_at | | |

### `leads`
`id, created_at, name, contact (телефон/@username), channel (tg/whatsapp/call), car_id null, source_page, context (квиз-ответы json), utm_* , ym_client_id, status (new/in_work/won/lost), manager, tg_message_id`.

### `tg_subscribers`
`chat_id, username, first_name, started_at, start_param (car_123 / site / quiz), is_blocked`.

### `settings`
Курс CNY/USD→RUB (авто с ЦБ + ручная надбавка), логистика по странам, комиссия, таблица утильсбора/пошлин. **Ставки не хардкодим** — правила меняются, Руслан проверяет значения.

## 4. Логика цены «от»

```
price_from_rub = round_down_to_10k(
    (price_usd + export_fee_usd + port_fee_usd) × курс
  + логистика(страна)
  + таможня(объём, возраст, тип двигателя)
  + утильсбор(мощность, возраст)
  + комиссия
)
```
- Для б/у — **всегда «от»** и чуть ниже реальной (договорились на созвоне — это крючок на заявку).
- Под ценой: «Точная цена под ключ — по запросу» → кнопка заявки.
- Курс USD в выдаче донора клиент не видит; источник не показываем.
- Если формула не нужна — Руслан просто вписывает цену руками (поле-оверрайд).

## 5. Админка (экраны)

**5.1 Парсер → «Подбор в витрину»** (на базе существующего списка объявлений)
- Фильтры: марка, модель, год от/до, **мощность до** (нужен новый фильтр), пробег, цена, топливо, кузов, привод, страна.
- Пресет-кнопка **«Проходные»**: ≤160 л.с. + возраст 3–5 лет.
- Чекбоксы + «Добавить в витрину» (черновики) → дубли по одной модели/комплектации подсвечиваются.

**5.2 Витрина**
- Таблица карточек: обложка, название, цена «от», статус, хит, порядок (drag&drop).
- Кнопки: «Новая карточка», «Опубликовать», «Снять», «Пересобрать сайт» (если вариант A).

**5.3 Редактор карточки**
- Поля из §3, предзаполненные; RU-перевод значений через словарь (`Gasoline→Бензин`, `Range Extender→Последовательный гибрид`, `Rear-Wheel Drive→Задний` …).
- Фото: выбрать из фото донора (галочки) + загрузить свои, кроп 4:3, переставить обложку. Позже — кнопка «единый фон» через AI (Руслан хотел фирменный стиль как в канале).
- Блок «Расчёт цены» с разбивкой и полем оверрайда.
- Превью карточки как на сайте.

**5.4 Заявки**
- Список с фильтром по статусу и источнику, смена статуса, комментарий. Дублирует то, что приходит в Telegram — чтобы ничего не терялось.

## 6. Заявки в Telegram (продающая часть)

### 6.1 Поток
```
Сайт: форма (карточка / квиз / контакты / hero)
   → POST https://vanauto-api.neeklo.ru/api/v1/leads   (НЕ напрямую в Bot API: токен бота нельзя светить в браузере)
   → сохранение в leads
   → бот шлёт в группу «VAN2KAUTO заявки»:

   🔥 Новая заявка #128
   Авто: Mazda CX-5 2023 AWD — от 2 890 000 ₽  (ссылка на карточку)
   Имя: Иван · Связь: Telegram @ivan
   Источник: /catalog/mazda-cx-5… · utm: yandex / cpc / cx5
   Квиз: бюджет до 3 млн, кроссовер, полный привод
   [✅ Взял в работу]  [❌ Спам]

   → кнопка ставит статус и имя менеджера в БД, сообщение редактируется
   → клиенту на сайте: «Заявка принята, ответим в течение 15 минут»
```

### 6.2 Защита и закон
- Honeypot-поле + rate-limit по IP + проверка телефона/@username (уже есть на фронте).
- Чекбокс согласия на обработку ПДн + страница политики (152-ФЗ) — обязательно, иначе риск штрафа.
- Повтор при ошибке Telegram: заявка уже в БД, отправка ретраится очередью.

### 6.3 Вторая дверь — сразу в бота
Кнопка «Написать в Telegram» ведёт в бота с deep-link: `t.me/van2kauto_bot?start=car_mazda-cx-5-2023`.
Бот: приветствие → «Вас интересует Mazda CX-5, верно?» → бюджет (кнопки) → «когда удобно связаться» → заявка в ту же группу. Плюс пользователь попадает в `tg_subscribers`.
Это лучше голой ссылки на личку Руслана: источник фиксируется, а база подписчиков растёт.

### 6.4 Рассылки (согласовано на созвоне)
- **Автопостинг в канал — НЕ делаем** (Руслан против: «бездушно»).
- Рассылка подписчикам бота — из админки: выбрал карточки → текст → «Отправить N подписчикам». Сначала тестовая отправка себе.

### 6.5 Трафик канал ↔ сайт
- В карточке на сайте ссылка «Больше авто в канале @123auto».
- В постах канала — ссылки на карточки сайта с `utm_source=tg_channel` → видно в заявках, откуда пришёл клиент.
